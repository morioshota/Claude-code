- `README.md` … 仕様書。計算式、状態判定、**変更してはいけない設計判断**、バージョン履歴

## このツールは何か

建設現場の材料在庫を、日々の使用記録と購入記録から管理する**単一HTMLの実務ツール**。
利用者は土木施工管理の実務者本人。デモではないので、**現場で使えること**が最優先。

## 絶対に守る制約（詳細は README.md）

1. 単一HTMLファイルを維持する。フレームワーク・バンドラ・ビルド工程を入れない
2. 外部依存ゼロ。CDNも使わない（オフラインの現場PCで動くこと）。グラフはcanvasに自前で描く
3. データは端末の localStorage だけ。サーバーに送らない。バックアップ導線を弱くしない
4. **表示は事実だけ。** アラートは「自分で決めた発注点に届いた」という到達の事実であって、
   「買え」「多すぎる」といった指示・評価は書かない
5. 記録は消さずに積む（棚卸は過去の書き換えではなく差分の追加）
6. 実務用語を勝手に言い換えない（発注点／リードタイム／棚卸／出庫・入庫 など）

## 作業のルール

### 計算ロジックを変えたら必ずテスト

```bash
node test/core.test.js      # 94項目。全部パスしてからコミットする
```

計算コアは `index.html` の `<script>` 冒頭にある DOM非依存の純関数群。
テストはそこを抽出して検証するので、**関数名とセクション区切りコメントを消さないこと。**

### 見た目を変えたら実描画で確認

環境内の Chromium（`/opt/pw-browsers/chromium-*/chrome-linux/chrome`）で開いて確認する。
スマホ幅（390px）も見ること——現場ではスマホから入力することがある。

### バージョンを上げたとき

`index.html` のヘッダコメント・`<title>`・画面ヘッダーのクレジット・`README.md` のバージョン履歴・
`site/assets/tools.js`（紹介サイトの台帳）の5か所を合わせて更新する。
