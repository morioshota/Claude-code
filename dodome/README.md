# 土留め検討ツール（Earth Retaining Work Planner）

道路工事・管路工事の仮設土留めについて、**掘削寸法から「数量」と「構造の目安」を同時に出す**
検討ツール。土量・ダンプ台数・土留め材の員数と、慣用法による必要根入れ長・断面応力度・切梁軸力を
1画面で確認でき、3Dビューで施工段階を送りながら納まりを目で見られる。

- 単一HTMLファイル（`index.html`）・ビルド不要・**完全オフライン動作**（three.js r128 を同梱）
- 公開URL（`main` にマージ後）: `https://morioshota.github.io/Claude-code/dodome/`
- ローカル確認: リポジトリのルートで `python3 -m http.server 8000` → http://localhost:8000/dodome/

制作者：Shota Onuma（土木施工管理／1級土木施工管理技士）

## ⚠ このツールの位置づけ（最重要）

**出力はすべて「検討用の参考値」であり、正式な設計計算書の代替にはならない。**

理由は3つ。この認識をUIからも README からも消さないこと。

1. **前提の質をツールでは担保できない。** 土留めの設計は土質定数（γ・φ・c）、地下水位、上載荷重の
   取り方で答えが何割も動く。土質調査結果に基づかない概算入力から出た数値は、式が正しくても
   結論の裏づけがない。
2. **提出物としての計算書は、拠り所となる指針に沿って作られ、設計者の照査を経て成立する。**
   ソフトの出力そのものが承認されるわけではない。
3. **市販の土留め設計ソフトと同等の照査項目までは持っていない。**（下記「行っていない照査」）

### このツールが行っていない照査

ボイリング・ヒービング・盤ぶくれ・たわみ量・根入れ部の支持力・切梁の座屈・偏土圧・
近接構造物の影響・**多層地盤**・弾塑性法・法面の安定（すべり）。

### 数値の出どころ

- **土質定数・変化率 L/C・部材の規格値・ダンプの荷台容積は、すべて「目安値」として入っている。**
  画面上で全部編集でき、書き換えると出典が「自分で入力」に変わってその端末に保存される。
- 部材ライブラリの `src` 欄が値の状態を示す。
  - `一般値` … 広く使われている値。それでも手元のカタログで確認すること
  - `要確認` … このツールの推定値。**必ずカタログで確認・上書きすること**
  - `要入力` … 規格値を入れていない（`Z: null`）。入れるまで断面照査を行わない
  - `自分で入力` … 利用者が上書きした値
- 軽量鋼矢板・アルミ矢板・ハット形鋼矢板は、開発時にメーカーのカタログを参照できなかったため
  **`要入力` にしてある**。断面係数を推定値で埋めるより、空にして「照査しない」ほうが安全と判断した。
  員数と長さは有効幅だけで出せるので、規格値が無くても数量は拾える。

## 対応している工法と掘削形状

| 工法 | 支持 | 断面照査 | 備考 |
|---|---|---|---|
| 簡易土留め（軽量鋼矢板・アルミ矢板の建込み） | 切梁 | 規格値を入れたら | 既定は `要入力` |
| 鋼矢板 自立式 | 根入れのみ | ○ | 根入れが深くなる |
| 鋼矢板 切梁式 | 切梁 | ○ | |
| 親杭横矢板 | 切梁 | ○ | Z は1本あたり。建込み間隔で壁1mあたりに換算する |
| 法面オープンカット | — | — | 土量のみ。法面の安定は検討しない |

- **線状トレンチ** … 断面（矩形または台形）× 延長。土留めは**両側2面**で拾う
- **矩形立坑** … 四周を土留め。法面つきは角錐台（プリズマトイド公式）で厳密に体積を出す

## 計算式

### 掘削土量

```
トレンチ（矩形）  V = B·H·L
トレンチ（法面）  V = (B + n·H)·H·L          ※台形断面。上底 B+2nH、下底 B
立坑（直壁）      V = X·Y·H
立坑（法面）      V = H/6 ×( A下 + 4·A中 + A上 )   ※角錐台。この形なら厳密解
```

### 土量の変化と収支

```
ほぐし = 地山 × L        締固め = 地山 × C        （逆は割り算）
基礎材(締固め)  = 床付け面積 × 厚さ
埋戻し(締固め)  = 掘削 − 構造物 − 基礎材
埋戻しに要る地山量 = 埋戻し(締固め) ÷ C
流用できる量    = min( 埋戻しに要る地山量 , 掘削地山量 × 流用率 )
購入土(地山換算) = 埋戻しに要る地山量 − 流用量        （負なら0）
残土(地山)      = 掘削地山量 − 流用量                （負なら0）
```

### ダンプ

```
ほぐし密度 = 湿潤密度 ÷ L
1台の積載(ほぐしm³) = min( 荷台容積 , 積載重量 ÷ ほぐし密度 )     ※山積みは容積×1.2
延べ台数   = 切上げ( 運搬ほぐし量 ÷ 1台の積載 )
1サイクル  = 片道 ×2 ＋ 積込荷卸
1日の回転数 = 切捨て( 運搬可能時間×60 ÷ 1サイクル )
運搬日数   = 切上げ( 延べ台数 ÷ (回転数 × 手配台数) )
```

### 土圧（ランキン式・壁面摩擦は見込まない＝安全側）

```
Ka = tan²(45° − φ/2)      Kp = tan²(45° + φ/2)

背面 p(z) = Ka·σv′(z) − 2c√Ka  ＋ 残留水圧 u(z)        ※主働が負になる範囲は 0
   σv′ = γt·z + q                       （地下水位以浅）
       = γt·hw + (γt−γw)(z−hw) + q      （地下水位以深）
   u   = γw(z − hw)
前面 pp(z′) = Kp·σv′(z′) + 2c√Kp        ※z′ は床付け面からの深さ。前面水圧は見込まない
```

### 必要根入れ長

受働モーメント ÷ Fs ≧ 主働モーメント を満たす最小の D を二分法で求める。回転の中心は工法で変わる。

| 工法 | 回転の中心 | 腕の向き | 主働を積分する範囲 |
|---|---|---|---|
| 自立式 | 壁体下端（つま先） | 中心から上向き（`sign:-1`） | 壁頭から下端まで（`zFrom = 0`） |
| 切梁式 | 最下段の切梁 | 中心から下向き（`sign:+1`） | **最下段の切梁から下だけ**（`zFrom = pivot`） |

**⚠ 切梁式で主働を壁頭から積分してはいけない。** 最下段の切梁より上の土圧は上段の切梁が受け持つ。
そこまで釣合いに入れると逆向きの大きなモーメントになって打ち消し合い、**根入れがほぼ0で返る**
（開発中に実際に踏んだ。回帰テストで見張っている）。

`施工上の最小根入れ長`（既定 1.5m・利用者が決める値）を下限として噛ませ、**どちらで決まったかを
画面に明記する**。ここで求まるのはモーメント釣合い上の必要値だけで、ボイリング・ヒービング・支持力から
決まる根入れは扱っていないため。

参考（φ=30°・γ=18kN/m³・c=0・q=10kN/m²・Fs=1.2・1段目GL−1.0m・段間隔2.0m のとき）:

| 掘削深さ H | 切梁の段 | 切梁式 D | 自立式 D |
|---|---|---|---|
| 3.0 m | GL−1.0 | 1.43 m | 3.67 m |
| 5.0 m | GL−1.0 / 3.0 | 1.99 m | 5.77 m |
| 8.0 m | GL−1.0 〜 7.0 | 2.43 m | 8.92 m |
| 12.0 m | GL−1.0 〜 11.0 | 3.37 m | 13.10 m |

### 断面力（慣用法）

- **切梁式＝単純梁法。** 支点（各段の切梁＋床付け面下の仮想支点）のあいだをそれぞれ単純梁として解く。
  最上段より上は片持ちの張出し。支点反力は、その支点に取り付く単純梁の端反力の和。
  この方法は**反力の総和が荷重の総和に厳密に一致する**（回帰テストで確認している）。
- **自立式＝片持ち。** `M(z) = ∫₀ᶻ q(t)(z−t)dt`。正味の側圧 q = 背面側圧 − 受働抵抗÷Fs（床付け面以深）。

```
断面照査   σ = M × 1000 ÷ Z          [M: kN·m/m, Z: cm³/m → σ: N/mm²]
親杭の場合  Z(壁1mあたり) = Z(1本あたり) ÷ 建込み間隔
切梁軸力   N = R × 切梁の水平間隔
腹起し     M = R·l²/10               ※連続梁として
```

## 変更してはいけない設計判断

1. **単一HTMLファイルを維持する。** フレームワーク・バンドラ・ビルド工程を入れない。
   現場PCへの配布とGitHub Pages配置の手軽さが失われる。
2. **外部依存は同梱した three.js r128 のみ。** CDN を使わない（回線の無い現場で3Dが死ぬ）。
3. **「検討用の参考値である」旨の注記を消さない。** ②構造検討タブの警告、④集計タブの
   ライブラリ注記、CSV/JSONヘッダの3か所にある。
4. **推定値で規格値の欄を埋めない。** 確認できない値は `要入力`（`Z: null`）にして、
   断面照査を「行わない」ほうを選ぶ。間違った断面がOK判定で出るほうが危険。
5. **どの式を使ったかを画面に出す。** ①と②の「計算に使った式」ブロックは、
   数値の根拠を利用者が追えるようにするためのもの。減らさない。
6. **計算コアは DOM に触れない。** `index.html` 冒頭の区切りコメント
   「① 計算コア ここから／ここまで」に挟まれた区間は純関数だけで構成し、
   `test/core.test.js` が抽出して検証する。**区切りコメントを消さないこと。**
7. **専門用語の表記を勝手に変えない。** 「床付け」「根入れ」「腹起し」「切梁」「ほぐし」
   「締固め」「地山」など、実務で通用する語を使っている。

## 開発

```bash
cd dodome
node test/core.test.js     # 計算コアの回帰テスト（88項目）
```

HTML を編集したら、埋め込み JS の構文も確認する。

```bash
node -e "
const fs=require('fs');
const h=fs.readFileSync('index.html','utf8');
const s=[...h.matchAll(/<script>([\s\S]*?)<\/script>/g)].map(m=>m[1]);
fs.writeFileSync('/tmp/x.js', s[s.length-1]);
"
node --check /tmp/x.js
```

**見た目の変更は、環境内の Chromium（`/opt/pw-browsers/`）で実描画してから提示すること。**
