## プロジェクト概要

**覆工板 最適勾配 検討ツール**（Optimal Grade Finder for Road Decking）

道路工事の仮設工で、覆工板の勾配を「既設舗装との高低差が最小になる」ように決定するための検討ツール。
既設舗装の実測高から最適な縦断・横断勾配を最小二乗的に算出し、高低差・すり付け長・管理値を出力する。

制作者：Shota Onuma（土木施工管理／1級土木施工管理技士）
利用者：本人および工事関係者。**現場PCで使う実務ツール**であり、デモではない。

## 絶対に守る制約

1. **単一HTMLファイル（`index.html`）を維持する。**
   フレームワーク、バンドラ、ビルド工程を導入しない。現場PCへの配布とNetlify配置の手軽さが失われるため。
2. **外部依存は three.js（r128）のみ。v1.1.0 で CDN をやめ、index.html に直接同梱した。**
   現場PCがオフラインでも 3Dビューが動く。新しいライブラリを足す場合は必ず事前に相談すること。
   同梱ブロックの差し替え手順は `CODE_STRUCTURE.md` を参照。
3. **グリッド入力表の軸の向きを変えない。** 行＝縦断(S)、列＝横断(T)。
   過去に一度転置したが「分かりにくい」という理由で元に戻した経緯がある。
4. **測点位置は必ず `getPositions()` 経由で取得する。**
   `i * dS` のような等間隔前提の計算を書くと、非等間隔対応が壊れる。
5. **管理値テーブルの列順を変えない。**（測点 → 横断T → 縦断S → …）
6. **専門用語の表記を勝手に変えない。**
   「床付け」「受桁天端」「すり付け」「覆工面」など。実務で通用する語を使っている。

## 作業のルール

### 計算ロジックを変更したら必ずテストする

```bash
node test/core.test.js
```

21項目の回帰テストがある。**全項目パスを確認してからコミットすること。**
計算コアは `index.html` の JavaScript 冒頭にあり、DOM 非依存の純関数群になっている。
テストはそこを抽出して検証する仕組みのため、**関数名やセクション区切りコメントを消さないこと。**

### 構文チェック

HTML を編集したら、埋め込み JS の構文を確認する。

```bash
node -e "
const fs=require('fs');
const h=fs.readFileSync('index.html','utf8');
const s=[...h.matchAll(/<script>([\s\S]*?)<\/script>/g)].map(m=>m[1]);
fs.writeFileSync('/tmp/x.js', s[s.length-1]);

node --check /tmp/x.js
```

## 既知の技術的な注意点

- **OrbitControls は使えない**（three.js r128 の配布物 `build/three.min.js` に同梱されていない）。
  3Dのカメラ操作はポインタイベントによる自前実装（`init3D()` 内の `cam` オブジェクト）。
- **three.js は `id="three-r128"` のスクリプトタグに丸ごと貼り付けてある**（約590KB）。
  この id を消さないこと。回帰テストと構文チェックは「属性の付かないスクリプトタグの
  最後のブロック＝アプリ本体」を抜き出す仕組みのため、id が無いと同梱ブロックが検査対象になる。
- **3Dビューは非表示中に canvas サイズが 0 になる。**
  タブ切替時に `resize()` → `update3D()` を遅延実行している（`switchView()` 参照）。
- **印刷のため renderer は `preserveDrawingBuffer: true`。** 外すと3Dが白紙で印刷される。
- **`update3D()` は毎回シーンを作り直す方式。** 差分更新はしていない。測点数が非常に多い場合は要注意。
- **localStorage キーは `fukko_tool_v1`。** 保存形式を変える場合はキーも変え、
  利用者に「初回のみ再入力が必要」と伝える必要がある。
- ブラウザのセキュリティ制約により、`prompt()` や `window.open()` はイベントハンドラ内で
  ブロックされることがある。ダイアログが必要ならカスタムモーダルで実装する。
